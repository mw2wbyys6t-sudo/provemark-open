# 交付与发布手册（Delivery）

目标：**小步、可回滚、可观测**地发布。

## 1. 提交与 PR

- 一个提交做一件事；提交信息写“为什么”而不是“改了啥”；
- PR 描述模板：问题 / 方案 / 验证方式 / 风险与回滚；
- PR 大小控制在可评审范围（建议 ≤400 行有效 diff）；
- 禁止把格式化、重命名、依赖升级混进功能 PR；
- 合并前必须绿：lint、类型、单测、集成、安全门禁（`provemark_guard`）。

## 2. 分支与版本

- 主干开发 + 短生命周期分支；分支存活时间以天计；
- 版本语义（SemVer）：破坏性变更升 major，兼容新增升 minor，修复升 patch；
- 发布标签对应唯一提交；CHANGELOG 面向使用者写行为变化；
- 热修复从发布标签拉分支，修完回合并主干，避免只修一条线。

## 3. CI 流水线

```text
提交 → lint/格式/类型 → 单元测试 → 构建 → 集成测试 → 安全扫描
     → 制品（镜像/包）→ 部署预发 → 冒烟 → 灰度 → 全量
```

- 每一阶段失败即阻断；跳过检查要有书面理由与到期时间；
- 构建产物不可变：同一 digest 从预发晋级到生产，禁止重新构建；
- 依赖安装用锁文件（`npm ci`、`uv sync --locked`、`go mod download`）；
- Action 固定到 SHA，权限最小化（`permissions: read-all` + 按需提升）。

## 4. 发布策略

| 策略 | 适用 | 要点 |
| --- | --- | --- |
| 滚动 | 无状态服务 | 就绪探针、优雅停机、连接排空 |
| 蓝绿 | 需要快速整体回滚 | 双倍资源、切流量、验证后回收 |
| 金丝雀 | 高风险变更 | 按比例放量 + 关键指标对比 + 自动回滚阈值 |
| 功能开关 | 解耦发布与上线 | 开关有默认值、有清理计划、避免开关爆炸 |

- 数据库迁移与代码发布顺序要兼容（先加后删，见 `data-playbook.md` §4）；
- 回滚预案写进 PR：回滚命令、数据是否可回退、谁执行。

## 5. 可观测性门禁

- 发布前定义 SLI：错误率、p95/p99 延迟、饱和度；有阈值与告警；
- 发布后观察窗口（如 30 分钟）内指标对比基线；异常自动回滚；
- 日志带 release 版本与 request id，便于按版本定位；
- 关键业务指标（下单成功率等）与发布联动看。

## 6. 依赖与安全更新

- 依赖升级小步常做，避免一次性大升级；
- 漏洞修复优先于功能开发（按可利用性排序）；
- 锁文件随 PR 更新；升级后跑全量测试 + 冒烟；
- 供应链：新依赖先看维护活跃度、许可证、star/下载不是安全证据。

## 7. 事故响应（发布相关）

1. 止血：回滚/关开关/限流，先恢复；
2. 定位：按版本/时间线对比指标与日志；
3. 沟通：影响面、当前状态、下次更新时间；
4. 复盘：根因 + 防再发行动项（见 `debugging-playbook.md` §7）。

## 8. 边界

- 发布流程要与团队规模匹配：小团队别照搬大厂多环境矩阵；
- 自动化不是目的：没有验证与回滚的自动化只是“更快地犯错”；
- 所有发布策略都以“可观测 + 可回滚”为前提。
