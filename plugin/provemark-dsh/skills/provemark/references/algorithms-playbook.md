# 算法与数据结构手册（复杂度 · 选型 · 反模式）

这份手册管的是“**代码会不会随着数据量增长而崩掉**”。安全管“被打”，工程管“能跑”，算法管“跑得完”。
静态扫描只能指出可疑模式，真正的复杂度判断仍要人做——所以这里给的是判据和检查表。

## 1. 先算清楚规模

| 数据量 | 可接受的量级 | 说明 |
| --- | --- | --- |
| n ≤ 1e3 | O(n²) 勉强可用 | 但别在请求路径上 |
| n ≤ 1e6 | O(n log n) / O(n) 必需 | O(n²) 直接不可用 |
| n ≥ 1e7 | O(n) 也要小心常数 | 流式/分块/外部排序 |

**先问三个问题**：数据量级多少？调用频率多少？是请求路径还是离线任务？
同一个 O(n²)，每天跑一次的离线脚本和每请求执行一次的代码，严重性差两个数量级。

## 2. 数据结构选型速查

| 需求 | 正确选择 | 常见错误 |
| --- | --- | --- |
| 成员判断 | `set` / `dict`（O(1)） | 在循环里 `x in list`（O(n)） |
| 队列 | `collections.deque` / 头指针 | `list.pop(0)`（O(n)） |
| 栈 | `list` 的 `append`/`pop()` | — |
| 优先队列 / Top-K | `heapq` / 堆 | 每次 `sorted()` 取最小 |
| 有序查找 | `bisect` / 平衡树 | 线性扫描 |
| 计数 / 分组 | `Counter` / `defaultdict` | 双重循环统计 |
| 去重保序 | `dict.fromkeys` | `set` 后丢顺序 |
| 区间合并 | 排序后扫描 | 两两比较 |
| 并查集 | 路径压缩 + 按秩合并 | 每次遍历找根 |
| 前缀和 / 差分 | 预处理 O(n) + O(1) 查询 | 每次区间求和 O(n) |
| 图遍历 | BFS（最短步数）/ DFS（连通性） | 递归无 visited |
| 滑动窗口 | 双指针 | 每次重算子数组 |
| 字符串拼接 | 列表 + `join` | 循环里 `+=`（O(n²)） |
| 大表聚合 | 向量化 / 一次 `concat` | 循环里 `pd.concat`（O(n²)） |
| 逐行处理 DataFrame | 向量化 / `itertuples` | `iterrows` |

## 3. 常见算法的关键点

- **排序**：比较器要满足全序（别在比较器里写不稳定逻辑）；大对象排序只对 key 排序；`n` 很大且只要 Top-K 用堆。
- **二分**：区间定义（左闭右开）统一；`mid = lo + (hi - lo) // 2` 防溢出；找边界时明确 `lower_bound`/`upper_bound`。
- **哈希**：自定义对象做 key 必须同时实现 `__hash__`/`__eq__`；可变对象不能做 key；哈希顺序不稳定，别依赖遍历顺序。
- **图**：BFS 求无权最短路；Dijkstra 要求非负权；拓扑排序先判环；DFS 递归深度大时改迭代。
- **动态规划**：先写状态定义与转移方程，再写实现；注意初始化与边界；空间可滚动数组优化。
- **贪心**：必须能证明局部最优推出全局最优，否则就是错的；用对拍验证。
- **随机**：可复现实验固定种子；`random.shuffle` 用 Fisher-Yates（Python 自带）；安全场景用 `secrets`（见 `VUL-009`）。
- **递归**：必须有终止条件；重复子问题加 memo；深度可能超限时改迭代。

## 4. 数值与精度（AI 最容易写错的地方）

- **浮点比较**：不要 `a == b` 判断浮点相等，用 `math.isclose` / 误差阈值；金额用整数分或 `Decimal`，别用 float。
- **整数溢出**：Go/Java 的 int 有范围；Python 没有但转 numpy 时注意 dtype；SQL 自增 ID 注意上限。
- **除零**：除法前判零；取整方向（`//` 是向下取整，负数会出乎意料）要明确。
- **精度**：`sum` 大量浮点用 `math.fsum`；顺序会影响结果；坐标/统计量注意有效数字。
- **时间**：跨时区/夏令时用带时区的时间；时间戳单位（秒/毫秒）别混。

## 5. AI 生成代码的算法反模式（对应规则）

| 反模式 | 复杂度后果 | 修法 | 规则 |
| --- | --- | --- | --- |
| 循环里 `requests`/`fetch` 逐条请求 | N 次串行往返 | 批量接口 / 异步限并发 | AI-021 |
| 循环里字符串 `+=` | O(n²) 内存复制 | 列表 + `join` | AI-022 |
| 循环里 `pd.concat` | O(n²) 表复制 | 收集列表后一次 `concat` | AI-024 |
| `list.pop(0)` / `insert(0, x)` | 每次 O(n) | `deque` / 读指针 | AI-025 |
| `df.iterrows()` 逐行 | 慢 1–2 个数量级 | 向量化 / `itertuples` | AI-026 |
| 循环里 `await` 串行 | 延迟线性累加 | `gather`/`Promise.all`（限流） | AI-016 |
| 循环里查库 | N+1 | 批量 `IN` / 预加载 | AI-017 |
| 每次取最小都 `sorted()` | O(n² log n) | 堆 | 见 §2 |

## 6. 怎么验证（比“看起来对”可靠）

1. **对拍**：写一个暴力版本，随机小数据对比结果（算法题与业务规则都适用）；
2. **性质测试**：排序后有序、去重后无重复、幂等操作重复执行结果不变（Hypothesis / fast-check）；
3. **基准**：用 `timeit` / `hyperfine` / pytest-benchmark 量真实数据量，不要凭感觉优化；
4. **数据量放大**：把 n 放大 10 倍看耗时曲线，区分 O(n) 与 O(n²)；
5. **边界**：空输入、单元素、全相同、极值、负数、超长字符串。

## 7. 边界

- 静态扫描**无法证明复杂度**：它只能指出“这个写法在常见数据量下会退化”，是否真慢要测；
- 规则覆盖的是高频反模式，不是算法正确性证明；算法本身对不对要靠对拍/性质测试；
- 没有“所有算法知识”：具体问题选型仍以数据规模、访问模式和实测为准。
