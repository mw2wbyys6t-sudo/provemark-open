# 测试手册（Testing）

目标：**用最低成本获得“改坏了会知道”的信心**。测试是资产，不是指标。

## 1. 测试层级与成本

| 层级 | 测什么 | 成本 | 建议占比 |
| --- | --- | --- | --- |
| 单元 | 纯逻辑、边界、算法 | 低 | 多 |
| 集成 | 与 DB/HTTP/队列的真实边界 | 中 | 关键路径 |
| 契约 | 服务间接口/OpenAPI 兼容 | 中 | 有跨服务时 |
| 端到端 | 少量关键用户旅程 | 高 | 少而精 |

原则：**测试金字塔**——底层多、顶层少；端到端只覆盖“坏了会赔钱”的路径。

## 2. 该测什么

- 新行为（feature）与修复（regression）必须有用例；
- **边界**：空、单元素、极值、重复、超长、负数、零；
- **错误路径**：超时、失败、部分成功、重试、权限不足；
- **契约**：输入输出格式、状态码、错误体；
- **并发/顺序**：至少有一条用例证明重复执行安全（幂等）。

## 3. 不该测什么

- 实现细节（私有方法调用次数、内部数据结构形状）——除非是契约；
- 框架/语言本身的行为；
- 为了覆盖率凑数的无断言用例。

覆盖率是**下限信号**：高覆盖率不等于高质量，低覆盖率一定有问题。

## 4. 测试替身（test double）

- 用**契约替身**（fake）代替 mock 框架，减少与实现耦合；
- 外部服务用本地 stub（HTTP 录制/回放），测试可离线、可重复；
- 时间/随机/ID 生成注入，别依赖真实时钟与随机；
- 数据库用真实引擎（容器/临时库），内存库行为差异会埋雷。

## 5. 测试数据

- 用工厂/构造器造数据，避免大段手工 fixture；
- 每条测试自建数据、自清理，不依赖执行顺序；
- 不写真实 PII/密钥；敏感字段用占位；
- 大数据集用生成器/采样，别把 10MB 文件塞进仓库。

## 6. 不稳定测试（flaky）治理

常见原因：顺序依赖、共享状态、真实网络/时间、随机种子、异步未等待、端口/资源冲突。
处理：先隔离（单独跑 100 次）→ 定位根因 → 修测试或修实现；**禁止用 retry 掩盖**。

## 7. 性质测试与对拍

- 性质测试（Hypothesis / fast-check）：验证“排序后有序”“去重后无重复”“编码解码往返”这类不变量；
- 对拍：写一个暴力版本，在随机小数据上对比结果——算法与业务规则都适用；
- 差分测试：新旧实现同时跑，对比输出（迁移/重构时最有效）。

## 8. CI 里的测试

- 提交前：快测（单元 + lint + 类型）；
- PR：全量单元 + 集成 + 契约；
- 合并后：端到端 + 性能基线（有预算时）；
- 测试必须可并行、可重跑、失败信息可定位（用例名 + 输入 + 断言差异）；
- 门禁：新代码不得降低通过率；新增用例不允许 flaky（重跑两次仍失败视为失败）。

## 9. 边界

- 测试不能证明没有 bug，只能证明“这些情况没问题”；
- 测试维护成本要算进设计：难测的代码通常是耦合太深；
- 没有产线数据时，测试用例的优先级靠风险评估，不靠感觉。
