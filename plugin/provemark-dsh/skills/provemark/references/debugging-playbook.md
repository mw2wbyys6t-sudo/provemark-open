# 调试手册（Debugging）

目标：**先让问题可复现，再让假设可证伪**。不要一上来改代码。

## 1. 调试顺序

1. **复现**：固定输入、环境、版本、时序；记录命令与输出；
2. **缩小**：二分定位（提交、文件、函数、行），先确认“哪一半还坏”；
3. **观察**：日志/断点/追踪，看真实值，不看猜测；
4. **假设**：一次只验证一个假设，写下预期结果；
5. **修复**：改最小面，先加复现测试；
6. **回归**：跑相关测试 + 一次全量；检查是否引入新问题；
7. **记录**：为什么坏、怎么发现、如何防再发。

## 2. 常见故障签名 → 先查什么

| 现象 | 先查 |
| --- | --- |
| 本地好、线上坏 | 配置/环境变量、依赖版本、时区、locale、数据量、NAT/网络策略 |
| 偶发失败 | 并发/竞态、共享可变状态、超时、重试、缓存、时钟 |
| 空指针/undefined | 上游返回空、缓存穿透、初始化顺序、可选字段 |
| 越界/off-by-one | 区间定义（开闭）、分页 offset、切片终点 |
| 编码乱码 | 字节 vs 字符串、UTF-8 声明、BOM、数据库排序规则 |
| 时间错 8 小时 | 时区没显式、naive datetime、UTC/本地混用 |
| 越跑越慢/内存涨 | 缓存无上限、监听器/连接未释放、循环引用、大对象驻留 |
| 死锁/卡死 | 锁顺序、事务里做网络调用、连接池耗尽 |
| 数据不一致 | 事务边界、幂等、重试、缓存与库不同步、并发更新丢失 |

## 3. 二分与最小复现

- **git bisect**：能稳定复现的回归，最快定位到提交；
- **二分输入**：删掉一半数据/字段/步骤，看是否仍复现；
- **最小复现**：一个脚本、一个请求、一个失败用例；能贴进 issue 才算完成；
- **对照实验**：只改一个变量；记录“改前/改后”的输出。

## 4. 日志与可观测性的正确用法

- 日志要能回答：**哪个请求、哪个用户（脱敏）、哪一步、耗时多少、结果如何**；
- 用 request id 串联一次请求的所有日志；
- 错误日志带堆栈与上下文，但**不要打印 PII/密钥**；
- 临时调试输出用完即删（`AI-020`/`AI-008` 会提醒）；
- 线上优先看指标（错误率、延迟分位）与追踪，而不是 grep 日志。

## 5. 并发/竞态排查

- 先判断是否共享状态：全局变量、缓存、连接、文件、数据库行；
- 用“先查后写”要意识到 TOCTOU：改用唯一约束/乐观锁/原子操作；
- 锁：固定加锁顺序、缩小临界区、不在锁内做网络 IO；
- 用压力/重复执行放大竞态（1 次能过不算过，跑 1000 次）；
- 时钟相关的用注入时钟，别依赖 `sleep` 碰运气。

## 6. 测试相关

- 不稳定的测试（flaky）先当 bug 查：顺序依赖、共享 fixture、真实时间/网络、随机种子；
- 测试失败要能本地复现；不能复现就先补日志/种子，不要“重跑通过”就放过；
- 修 bug 的 PR 必须包含失败用例（先红后绿）。

## 7. 事故复盘模板（Postmortem）

- 时间线（发现→定位→止血→恢复）；
- 影响面（用户/数据/时长）；
- 根因（技术 + 流程，如“无超时 + 无重试上限”）；
- 为什么没更早发现（监控/测试/评审缺口）；
- 行动项（负责人 + 截止时间），至少一条是**防再发**而不是“下次注意”。

## 8. 边界

- 调试是证伪过程：没有观察数据的“我觉得”不算结论；
- 线上止血优先于根因（回滚/开关/限流），根因分析随后做；
- 无法复现时，先加可观测性，再等下一次出现。
