# mock-service（Provemark 演示仓库）

这是一个**故意做坏**的示例仓库，用来验证 Provemark 能不能把该抓的问题都抓出来。
里面的密钥、邮箱、证件号、卡号全部是假的，仅用于演示，不要照抄。

## 怎么跑

环境要求：Python 3.11+。先把 Provemark 跑起来，二选一：

**方式一：可编辑安装（推荐，之后直接用 `provemark`）**

```bash
cd ..                        # 回到 Provemark 源码目录
python -m pip install -e .
provemark --version          # 输出 provemark 0.4.0
```

**方式二：不安装，直接跑源码（之后用 `python -m provemark`）**

```bash
export PYTHONPATH=$(cd .. && pwd)   # 指向 Provemark 源码目录
python -m provemark --version       # 输出 provemark 0.4.0
# Windows PowerShell：$env:PYTHONPATH = (Resolve-Path ..).Path
```

装好后回到 mock 仓库根目录，下面命令都在这里执行。示例统一写 `provemark`，用方式二时替换成
`python -m provemark`（例如 `python -m provemark scan . --offline`）。

```bash
# 扫描：--offline 跳过漏洞与依赖许可证查询，联网才会触发 LIC-009
provemark scan . --offline
provemark scan .

# 生成三份声明骨架
provemark notices  .   # 会联网查依赖许可证；加 --offline 只用本地缓存
provemark ai-usage .   # 纯本地，无 --offline
provemark vendored .   # 纯本地；文件已存在时加 --force 才会覆盖

# 三个子命令都支持 --print：只打印内容、不写文件
provemark notices . --print
```

`VENDORED.md` 把没有来源的目录标成「待补齐」，等人工补上游地址与 commit。生成的声明都以
`<!-- generated by provemark ... -->` 开头，手写内容请放别的文件，重新生成不会覆盖手写版本。

### 3. 自动修复

`fix` 只补声明与配置类文件，不改业务代码；默认只预览，加 `--apply` 才写盘。以下在仓库副本上执行，
避免把演示仓库改成「已修复」状态：

```console
$ provemark fix .
可自动修复：
  · 追加 .gitignore（17 行）
  · 创建 SECURITY.md
  · 创建 .provemark.toml

这是预览（不会改动任何文件）。确认后执行：provemark fix --apply

$ provemark fix . --apply
可自动修复：
  · 追加 .gitignore（17 行）
  · 创建 SECURITY.md
  · 创建 .provemark.toml

  已追加 .gitignore
  已创建 SECURITY.md
  已创建 .provemark.toml
```

写入内容：

- `.gitignore` 追加 17 行（`.env`、`.env.*`、`*.pem`、`*.key`、构建产物等），原有规则保留；
- `SECURITY.md` 是漏洞披露模板；
- `.provemark.toml` 的 `license` 从 `LICENSE` / 清单文件推断，这里是 `GPL-2.0-only`，不会硬编码成 Apache-2.0。

重扫后卫生维度从 3 条降到 1 条：`HYG-003`（缺 SECURITY.md）和 `HYG-005`（.gitignore 漏 `.env`）消失，
只剩缺归因文件的 `HYG-014`。

`LIC-009` 这类依赖冲突不会被 `fix` 改掉——它只补声明，依赖换不换由你决定。代码层面的修复走
`provemark scan . --ai-prompt fix.md`，生成交给 AI 代理的指令文件。

## 这个仓库应该扫出什么

| 维度 | 预期命中 | 说明 |
| --- | --- | --- |
| 凭据 | `SEC-001` ×1（合并 3 处）、`SEC-017` | 同一个 OpenAI 密钥出现在 `.env`、`config.py`、`legacy.py`，另有一份 base64 编码版本；合并后只算一条 |
| 敏感数据 | `PII-001/002/003/004/005/006` | 邮箱、手机号、NRIC、卡号、日志打印 PII、批量邮箱快照 |
| AI 风险 | `AI-004`、`AI-012`、`AI-013` | 吞异常的 `except: pass`、幻觉依赖、有 CLAUDE.md 但没 AI_USAGE.md |
| 供应链 | `SCP-002/004/007/013` | `*` 版本、拼错的 `lodahs`、Action 未固定 SHA、CI 给了 `write-all` |
| 许可证 | `LIC-009`（联网或已有缓存）、`LIC-007` | GPL-2.0-only 项目引入 Apache-2.0 的 `requests`，同时项目许可证不在白名单 |
| 卫生 | `HYG-005`、`HYG-014` | `.env` 没被忽略、缺 THIRD_PARTY_NOTICES |
| Vendored | `SCP-014` | `vendor/foo` 有 LICENSE，但没有 VENDORED.md |

## 目录说明

- `vendor/foo/`：模拟手工拷进来的第三方代码（MIT），没有来源记录；
- `data/users.json`：模拟"不小心提交了一批真实邮箱"；
- `.env`：演示 `.gitignore` 漏掉 `.env` 的后果（值仍是假的）；
- `LICENSE` 是 GPL-2.0 的**节选**，只为让许可证识别能命中，不构成完整授权文本。
